04

오늘(2차시)의 목표

  • 심리척도의 구조(문항 → 척도 점수)와 역채점의 이유를 설명한다
  • 코드북으로 변수명 · 값 라벨 · 응답 범위를 해독하고 join 키(PID) 를 판별한다

Step 1 — 왜 한 번 안 묻고 열 번 묻나 🧠

"요즘 스트레스 있어?" 한 번이면 될 것 같은데, MAPS 는 10문항을 쓴다.

① 한 번의 측정은 흔들린다
그날 기분, 해석 차이 = 측정 오차.
여러 문항의 평균이 오차를 상쇄한다.

② 마음은 여러 면을 가진다
학교 · 동네 · 언어 · 정체성 —
한 질문으로는 한 면밖에 못 본다.

문항(item) 여러 개 → 묶음이 척도(scale) → 답의 평균이 척도 점수(scale score)

부분 응답 규칙: min_valid_items: 8 — 10문항 중 8개 미만 응답이면 점수를 결측 처리한다.

Step 1 — 실데이터로 척도 점수 내보기

w6 = pd.read_csv(W6, na_values=["", " "]) part6 = w6[w6["SURVEY1_w6"] == 1] # 6차 실제 참여자 1,329명 items = [f"s_accul_str_{i:02d}_w6" for i in range(1, 11)] score = scoring.scale_score(part6, items, method="mean", min_valid_items=8) # → 평균 ≈ 1.4 · 범위 1~4 (대부분 낮은 쪽 — 4차시 클래스 불균형의 복선)

주의 파이프라인과 같은 모듈(maps_risk.scoring)을 쓴다 — 수업과 분석이 어긋날 수 없다. 그리고 이 점수는 아직 역채점 미적용 상태다 → 다음 Step.

08

Step 2 — 역채점: 왜 거꾸로 묻나 ⚠️

설문에는 일부러 방향을 뒤집은 문항이 섞인다 — 내용을 안 읽고 전부 "그렇다"에 찍는 묵종 편향(acquiescence bias) 을 걸러내기 위해서다.

대가: 채점이 복잡해진다. 역방향 문항을 그대로 평균 내면
높은 스트레스와 낮은 스트레스가 서로 상쇄된다 — 척도 전체가 조용히 무의미해진다.

🔴 함정: MAPS 코드북의 값 라벨은 전부 정방향 표기(1=전혀 그렇지 않다 …)다.
라벨만 봐서는 역채점 문항을 찾을 수 없다 → 문항 텍스트를 사람이 읽는다.

09

Step 2 — 공식: (min + max) − x

def reverse_code(x, scale_min, scale_max): return (scale_min + scale_max) - x reverse_code(1, 1, 4) # → 4 (1↔4) reverse_code(2, 1, 4) # → 3 (2↔3) reverse_code(reverse_code(3, 1, 4), 1, 4) # → 3 두 번 뒤집으면 원래대로

이 줄이 하는 일 최소값+최대값에서 원점수를 빼면 양 끝이 서로 교환된다. 두 번 적용하면 원위치(involutive) — 이 성질을 tests/test_scoring.py 가 검사한다.

Step 2 실습 — 이 문항, 뒤집어야 하나

척도 방향: "점수가 높을수록 스트레스가 크다". 다음 중 방향이 반대인 문항은?

🖐 먼저 각자 판단하게 한 뒤 오른쪽 답을 연다.

s_accul_str_03 "한국에 사는 것에 스트레스를 받는다" → 정방향 s_accul_str_05 "주변에서 한국 사람처럼 행동하라고 스트레스를 준다" → 정방향 s_accul_str_08 "우리 동네 사람들은 우리 식구를 못살게 군다" → 정방향 s_accul_str_10 "외국인 부모님 나라보다 한국에서 더 잘 살 수 있을 것이다" → 역채점 후보 # ← 이 문항만 긍정 방향

⚠️ 노트북의 판단은 후보일 뿐이다. 최종 결정은 조사표 원문과 대조해 variables.yaml 의 reverse_items 에 기록한다. 그리고 3차시 Cronbach α 가 교차 검증한다 — 역채점을 틀리면 α 가 뚝 떨어진다.

Step 3 — 실데이터 컬럼명 규칙

실데이터 컬럼명 = 코드북 변수명 + "_w차수" s_accul_str_01 + _w5 → s_accul_str_01_w5 # 2015, 중2 s_accul_str_01 + _w6 → s_accul_str_01_w6 # 2016, 중3

이 규칙 자체도 추측이 아니라 실측으로 확인된 것이다 (체크리스트 §0).

1차시의 문장과 연결 — "같은 척도라도 연도가 다르면 역할이 다르다": _w5 는 feature, _w6 스트레스는 target.

13

Step 3 — PID vs ID: 함정 (실습)

w5["PID"].duplicated().sum() # → 0 개인 ID — 중복 없음 w5["ID"].duplicated().sum() # → 10 가구 ID — 형제자매 10쌍! join_key = "___" # ← 어느 쪽인가

ID(가구)로 join 하면 형제자매 행이 교차로 짝지어져 행이 조용히 불어난다 — 에러도 안 난다. 그래서 build_dataset.py 는 ID 중복을 만나면 일부러 멈춘다.

"ID 라는 이름이 개인 식별자처럼 생겼다는 것 자체가 함정이었다. 이름이 아니라 코드북과 실측이 근거다."

Step 4 — 결측: 공백 한 칸의 의미

raw = pd.read_csv(W5) # 그냥 읽기 raw["s_accul_str_01_w5"].dtype # → object ← 문자열! mean() 불가 clean = pd.read_csv(W5, na_values=["", " "]) # 공백 = 결측으로 읽기 clean["s_accul_str_01_w5"].dtype # → float64 ← 숫자로 살아났다

결측 288개 = 5차 미참여자 288명 그 자체 — 결측이 무작위 빵꾸가 아니라 "그 해에 조사를 안 받은 사람"이라는 구조다.

에러가 나면 다행이다. 안 나고 이상한 값이 나오는 것이 최악이다.

Step 4 — 결측 코드 추측 금지 🔴

척도 문항에 숫자 결측 코드는 실측되지 않았다. 단 하나의 예외 — income_01_w5(월소득)에서 −9 관측.

사고 ① "아마 무응답이겠지"
→ 근거 없는 변환 (추측)

사고 ② 방치
→ 소득 평균에 −9 가 섞인다 (오염)

✅ 정답: 유저가이드에서 의미 확인 → 확인되면 missing_codes 에 추가 → 확인 전까지 그 변수를 쓰지 않는다.

16

Step 5 — 검증 워크플로: 사람이 게이트를 연다 🔍

① reports/codebook_candidates.md ← 자동 대조 체크리스트를 연다 ② 문항수 · 척도범위가 조사표(PDF)와 일치하는가 체크 ③ 문항 텍스트를 읽고 역채점 후보를 판단 ④ configs/variables.yaml 에 기록 items · expected_range · reverse_items · status: verified ⑤ meta.codebook_verified: true ← 이 한 줄이 게이트다

자동 대조가 보장하는 것은 "컬럼이 존재하고 값이 관측된다"까지.
의미와 방향은 기계가 판단할 수 없다 — 그래서 ④·⑤ 는 에디터에서 사람이 직접 한다.

"이 줄을 true 로 바꾸는 순간, 당신이 이 데이터의 보증인이 된다."

17

Step 5 — variables.yaml 의 구조

depression: wave: 5 status: verified # ← unverified → verified : 사람이 바꾸는 칸 expected_range: [1, 4] # 범위 검사의 기준 — 이것도 검증 대상 items: # 코드북에서 확인한 컬럼만 - ... reverse_items: [] # ③에서 판단한 역채점 문항

안전장치 status: verified 가 아닌 구성개념은 파이프라인이 자동으로 건너뛰고 보고서에 "미검증"으로 남는다 — 조용히 섞이는 일이 없다.

yaml 문법은 두 가지면 된다: 들여쓰기 = 소속, - 항목 = 리스트.

Step 5 실습 — 함께 판단할 논점 3개

  • 부모 양육태도 — "감독"과 "방임"은 방향이 반대라 합산 불가 → parenting_monitoring / parenting_neglect 로 분리 (역채점과 같은 원리가 척도 수준에서 나타난 사례)
  • 척도 범위 혼재 — 친구지지·교사지지는 5점, 대부분은 4점 → expected_range 를 척도별로 정확히 ("4점 점수와 5점 점수를 바로 비교해도 되나?" → 5차시 표준화의 복선)
  • 5차 미측정 — 자아존중감Ⅱ · 교우관계Ⅱ 등은 5차에 없다 → 제외. 없는 것을 억지로 채우지 않는다

"제안본이 다 해 줬는데 왜 손으로?" — 제안본은 존재를 검증, 사람은 의미를 검증. 이중 잠금이다.

Step 6 — ID join: 두 해를 한 표로

joined = w5.merge(w6, on="PID", how="inner") # 양쪽에 다 있는 PID 만 both = joined[(joined["SURVEY1_w5"] == 1) & (joined["SURVEY1_w6"] == 1)] # 참여 플래그 1 = 실제 응답

1차시 데모의 실전판이다 — set(w5) & set(w6) 의 merge 버전.

그런데 결과 행수가… 예상과 다를 것이다. 다음 슬라이드.

20

Step 6 — join 의 함정: 1,635 vs 1,321

5차 1,635행 + 6차 1,635행 → inner join → 1,635행 # 아무도 안 사라졌다?! 참여 필터 (SURVEY1_w5 == 1) & (SURVEY1_w6 == 1) → 1,321명 # 진짜 표본

매 차수 파일에는 전 패널 1,635명이 행으로 존재한다 (미참여자 응답은 공백=NaN).
그래서 — join 성공 ≠ 분석 표본. "join 이 됐다"와 "데이터가 있다"는 다른 말이다.

실측: 5차 참여 1,347 · 6차 1,329 · 둘 다 1,321 — 1차시 attrition 실습의 그 숫자다.

Step 7 — data_quality.md 함께 읽기

  • §1 응답자 ID — PID 유일성 ✅ (오늘 Step 3 이 표로 남은 것)
  • §2 병합 — 분석 표본 ≈ 1,321 · 패널 마모가 숫자로 남는다 → 8차시 한계 절의 재료

미검증 목록이 비어 있지 않아도 된다 — 전부 아니면 전무가 아니라, 검증된 것만으로 진행 가능한 구조다.
